# 央视网评45岁程序员求职难 程序员不就是吃的青春饭吗？

## 正文

我今年47岁，我罗列一下我的技术矩阵，简易的。

编程语言方面：

java 精通

c++ 熟练

c# 熟练

go 熟练

javascript 精通

python 精通

精通指的是，对这个编程语言以及相关的一些效用，类库，用法，注意事项都比较了解，基本上不会写出很奇怪的代码。比如就拿Java来说，如果你熟读并理解了effective Java里面的每一条，那么你就是精通Java的。并发问题不在此列，并发问题其实不是一个编程语言的独有问题。

熟练就是能够很好的使用，但是一些用法可能还是要去查。

还有一些冷门的编程语言我就不列了。反正估计也没有什么工作机会。包括scala，rust，等等。其实编程语言对我来说没有什么太大的差别了。所以根据我自身的感觉，一个合格的程序员，肯定能在2周之内熟悉和上手一个新的编程语言的。但是实际上，主流的编程语言就那么多。你在长达20年的工作过程中一般来说都会接触到。如果一个工作20年的程序员只熟悉java，那么……。我能说什么呢？

前端呈现技术方面：

首先OpenGL，DirectX包括3维软件的基础概念和开发方式我是了解的。而且我对巴比伦js比较熟悉，用这个干过实际的项目。

c# 的winform这个不用说了。

java的swing，这个也不用说了，但是我不是特别熟练。这个用的少。

Qt，比较熟练。而且我还有一些Qt调用activex（com）的经验。

js的前端框架：VUE熟练，React熟练，老掉牙的一些js框架，都用过。

webview方面：electron用过会用。微软的webview2用过会用。

我个人认为，webview2加上netcore是很有前景的技术，但是前提是你要会vue之类的js前端框架。

一般来说用户的界面需求上述技术都基本能够搞定了。

通讯方面：

TCP，IP这些属于基本的通讯。使用不同的编程语言利用tcp协议通讯可以说是一个程序员的基本功了。

websocket不多说。

还有别的就不多说了，现在90%的网络通讯都是基于TCP协议的。

数据库方面，就不罗列了。这个是任何一个程序员的基本功。就不多说了。

消息队列中间件。如果你不喜欢用tcp来写通讯的话，用这个也可以。但是这个玩意有风险。

如果在同一个技术框架内通讯是比较简单的，比如java，进程间通讯方法很多。什么微服务的通讯包装，多的很。但是在不同的编程语言和技术框架中通讯，还是用TCP最好。

另外还有串口通讯，这个在软硬结合项目中很常见。不过现在很多硬件设备都能支持TCP通讯了。所以这种传统的串口通讯已经不太重要了，多用于调试。另外蓝牙通讯也属于串口通讯的一种……。这些我都有不少经验。处理过很多这种软硬结合的项目。

操作系统方面：

linux是很熟悉了。

windows也很熟悉。这里多说一点关于windows。实际上，可能很多人不了解windows。其实window从win10开始，就已经是非常好的操作系统了。很多设计我觉得已经比linux还要好不少。所以建议大家多用win10，特别是1809之后的系统。早期还是不太行。

我说的熟悉不是使用方面的，而是能够使用系统提供的系统函数做一些“打磨”系统的事情。

编码方面：AES，BES这些都是常用的，我就不多说了。

编程技术方面：

我觉得我对编程技术的理解，写本书绰绰有余了。但是我觉得没有什么意义。因为不同的人对于技术的偏执和理解不一样。这个只能求同存异了。但是最起码我在编程上面的经验能够让人可以信赖。这两天具有一个鲜活的事实。到了讲故事时间了：公司有一个webrtc项目的文件上传功能，后台是我用c++实现的。中期测试的时候发现一个bug，说是出现上传列表的时候，上传会出现故障。具体表现就是上传失败，而且进度条突破300%。测试能够发现这个bug是很得意的。然后为此我们主管（比我年轻）还嘟嘟囔囔说，这个都搞不定会让人怀疑我们的能力。他这种充满情绪的话，我根本没有任何的反应，内心没有任何波澜。因为我非常清楚，情绪对于解决问题是无用的。我说，你说的对，我看看吧。然后就发现是前端那边，在出现上传列表的时候，一下发送了很多文件的请求导致的。前端同事花了一分钟解决了这个问题。其实这里面就暴露出来了公司管理的问题，出了问题为啥前端不排查？要后端排查呢？实际上c++处理并发问题，处理文件，排查问题都要比前端要困难的多。领导不懂这些吗？不是的。他就是在敲打你罢了。这些办公室政治的小玩意多的很。

总之编程技术方面需要积累的东西是很多的，比如说递归什么的。我觉得递归都处理不了，根本就不算一个程序员。因为递归是程序里面处理起来最基本的问题了。

还有处理树状结构的数据，这也是基本功。

递归下降算法我也写过几个……。其实这才是程序员的基本功。我觉得实现不出来递归下降算法的程序员我觉得都不太合格。

处理并发问题更是基本功。实际上，很多人都认识不到并发问题。这方面的故事可以说天天都在发生，我就不讲故事了。

当然其实我是程序员里面的异类。乱七八糟的东西懂的很多。很多人如果20年都只干java或者只写js我觉得也挺好。但是能不能积累出来丰富的经验我不好说。假如有一个朋友，找你接一个系统，可能钱不多10万，你敢不敢接呢？只懂java，大概率是不敢的吧。当然我也不敢，我正业都忙不过来，副业就算了。30万以上可以考虑。

结论：

对于程序员来说，我一直的看法都是，程序员就是专业编程的人。而不是只会用某一种语言编程的人。比如医生，确实需要分科。那是因为医生是很特殊的一种职业。但是程序员其实也分行业，不过不应该按编程语言来分。所以我一直很排斥什么前端程序员，后端程序员。什么java程序员，什么c#程序员。感觉这是很可笑的。一个程序员，说自己只懂编程可以，不能说自己只懂java。我觉得很多搞编程的人之所以就业困难，主要原因就是因为知识面太狭窄了。好像自己懂了java之后，就再也不能去学下c#，c++，或者python了。或者自己一直做后端开发，自己就学不会js了……。很奇怪，这些玻璃格挡都是自己给自己设置的而已。你这个不会，那个不会，这让用人单位也很头疼吧。而且根据我20年的从业经历来说，很多解决方案都需要跨平台，跨语言的。一个编程语言搞一个业务系统的时代是信息化的早期，这个时代已经渐渐过去了。而且随着技术的进步，特别是AI的发展，只会对程序员的要求越来越高。假如你固步自封，天天待在自己的舒适区。又怎么能抱怨社会，抱怨环境呢？而且你这种抱怨有什么意义呢？你是能改变环境吗？这点自知之明都没有吗？

我之前做招聘工作就老遇到这种人。干了十几年Java，Java经验确实可以，但是我们系统涉及很多部分，核心确实不是Java的。就这很多涉及Java抽象设计方面的东西也不太清楚。这种人就业能不困难吗？

而且，编程这个行业有一个很坏的风气，就是搞不清楚什么是工程，什么是学术。编程就是工程，讲究的是对技术的运用，而不是对技术的研究。如何用刀和如何冶炼一把刀完全是两回事。所以很多程序员不务正业，天天深入java虚拟机，其实这种对于学术的投入根本就是浪费时间，毫无意义。我之前面试的时候就经常被问什么restful相关的无聊问题……。什么路径规划，什么幂等……。这有什么意义呢？用户也不在乎这个。很多程序员趋入歧途，花了大量时间在没有意义的学术研究上，对虚拟机内部机制了如指掌，但是面对复杂的多系统并发问题却束手无策……。我能说什么呢？你是高手，但是可能你适合在高校里面搞研究，我们要的是能够解决问题的高手，而不是研究问题的高手。

最后我再说点肺腑之言吧。我是一个缺乏学术背景的老程序员。学术背景其实只有一些外企和大公司看重，但是工作面很狭窄，干时间长了人就在一个技术方向上扎根了。这其实也不是坏事，比如钻研算法或者精研虚拟机什么的，一些大企业也需要这样的人。但是这种人的需求非常少，而且基本上需要从小就努力，一般人根本做不到的。你最起码要有一个名牌大学的背景，然后研究生阶段学校老师也很重要。这种学术精英事业的可能性不大，不在我的讨论范围。如果你是这种人，可以随意鄙视我，我很服气。

我说的是普通程序员的情况。大多数程序员没有那么好的教育背景。也不太可能有什么学术上的成就。就算你去精研虚拟机，也只能算种业余爱好。就算你有什么结论，你也没有办法发论文。即使发了论文，别人也很难相信你的技术水平，因为你的教育背景不行。不是人人都是爱因斯坦的。

其实我一直是很反对在学术上去精研一些技术的。因为软件开发不是一种学术研究，也不是一种学术活动。实际上它是一种工程。所以我现在看到一些程序员觉得自己对一些理论非常的了解就很得意，就觉得自己高人一等。这是走错了路。

真正的程序员是要利用软件技术来解决用户的问题。而且要无所不用其极。Java好用就用Java。Python好用就用Python。C sharp好用就用C sharp。

而且根据我这么多年的工作经验。实际上真正赚钱的项目，大多数都是软硬结合的项目。纯粹的软件项目根本就不行。大多数都是赔本的。少数能够赚点钱。这是因为纯软件项目对于用户和开发人员来说都是要求很高的。如果你有经验的话你就会知道，其实用户有的时候根本搞不清楚他们自己想要什么。仅仅是一个交流过程，就是非常消耗时间和成本的。而软硬结合的项目就会好很多，用户往往的需求都是非常明确的。而且你还涉及很多设备，也很容易去销售。

很多这种程序员，特别是那种年轻的没有太多经验的成员，不知道怎么去积累经验。总以为去研究一些这种学术方面的东西，好像就是对自己能力的一种提升。实际上根本就是错误的方向。搞学术研究是不可能提升自己的这个解决问题的能力的。当然比天天吃吃喝喝打游戏要强一些。但也强的有限。我觉得还不如该休息的时候好好放松一下比较好。

你只能靠项目的经验，一步一个脚印来积累自己的技术能力。真的是没有什么捷径的。要么你就干脆走学术路线去考研究生，去考博士，去进大学，做教授。做研究员。如果你走了软件开发这条路，就不需要在学术上面投入过多的精力，毫无意义。我不是说学术没有意义，是你去投入是没有意义的。

所以我就我常说什么rest ful的路径规划呀，什么幂等性啊，这些具有学术内涵的东西，实际上对真正的项目影响非常非常的小。而且这种东西都有一个共同的特点，就是它属于一种知识，就算你现在不懂，但是如果你去看的话，看相关的资料的话，你可能在很短的时间内就能明白他是什么意思。

其实我觉得有时候多学几门编程语言，也比多研究这些理论要重要的多。当你闲暇的时候，其实你可以去学学一些编程语言。即使是你平时都不上这些。也是好的。

实际上编程要求的是你熟练的使用工具。包括编程语言，更多的是包含类库。我觉得对于Java程序员来说，很多时候，与其去研究虚拟机，不如去把Java的类库好好学习，学习里面有很多很多的东西，可能你都不知道，从来都没有听说过，也从来没有用过。

其实说实话，我经常会有失业的危机感。但是我并不畏惧从头再来。毕竟你能怎么样呢？人人都能抱怨，但是抱怨能解决什么问题呢？天天发牢骚，也不会让你找到更好的工作。天天批评别人技术水平很差，也不会提高你自己一点的技术水平。我们一步一个脚印一点点的积累自己的技术能力，我觉得总有一天会做得更多会做得更好，也可能会实现自己的梦想。无论你想做什么，天天抱怨是永远也做不成的。不要做一个唠唠叨叨的人吧。
